# VidShots - AI Long Video to Short Video Generator - TEST CASES

## 1. Introduction

This document outlines the comprehensive test cases for the VidShots application, a full-stack SaaS platform designed to convert long-form videos into viral short-form content using AI. It covers functional, integration, UI, edge case, security, performance, API, and negative testing scenarios to ensure a production-grade application.

The application leverages a modern technology stack including Next.js, Clerk for authentication, Neon PostgreSQL with Drizzle ORM, AWS S3 for storage, Ingest for workflow orchestration, Deepgram for transcription, Google Gemini for AI analysis, Remotion for video rendering, Jour for social media scheduling, and ARJet for security and abuse protection.

## 2. Scope

This test plan covers all features and workflows demonstrated and described in the provided technical overview, including:
*   User Authentication and Profile Management
*   Dashboard and Navigation
*   Long Video Upload and Storage
*   AI-powered Short Video Generation (Transcription, AI Analysis, Metadata Storage)
*   Short Video Preview and Caption Editing
*   Cloud-based Short Video Rendering and Download
*   Social Media Account Connection and Scheduling
*   Application Security and Rate Limiting

## 3. Test Environment

*   **Operating System:** MacOS / Windows (developer's choice), Linux (production server)
*   **Browsers:** Chrome (latest), Firefox (latest), Safari (latest), Edge (latest)
*   **Local Development:** Google Anti-gravity IDE, VS Code
*   **Runtime:** Node.js (latest LTS)
*   **Database:** Neon PostgreSQL (Local & Cloud Instances)
*   **Cloud Providers:** AWS (S3, Lambda)
*   **External APIs/Services:**
    *   Clerk.dev
    *   Ingest.dev
    *   Deepgram
    *   Google Gemini AI
    *   Jour API
    *   ARJet

## 4. Test Data (Assumptions)

*   **User Accounts:**
    *   New User (no existing data in Neon DB)
    *   Existing User (with uploaded videos, scheduled posts)
    *   User with connected social media accounts
*   **Video Files:**
    *   Small (e.g., < 10MB, < 30 seconds)
    *   Medium (e.g., 50-200MB, 5-10 minutes)
    *   Large (e.g., 1-2GB, 1-2 hours)
    *   Videos with clear speech, background music, varying scenes.
    *   Videos with no speech (e.g., silent footage).
    *   Unsupported file types (e.g., .txt, .pdf, .mp3).
*   **Social Media Accounts:**
    *   Valid accounts for Facebook, Instagram, TikTok, YouTube, Twitter.
    *   Accounts with revoked permissions.
*   **API Keys:** Valid API keys for all integrated services (Clerk, Deepgram, Gemini, Jour, ARJet, AWS S3, AWS Lambda).
*   **Database State:** Clean database for initial tests, pre-populated data for advanced scenarios.

**Assumption:** For rate limiting, the default is 2 video uploads per 24 hours per user, as specified.
**Assumption:** Supported video formats include common ones like MP4, MOV, WebM.
**Assumption:** The AI model (Gemini) can process transcriptions and consistently identify 4-5 high-engagement clips.
**Assumption:** Remotion Lambda is fully configured and operational on AWS as per setup instructions.
**Assumption:** Jour API is active and capable of connecting to and posting on multiple social media platforms.

## 6. Database Schema (Inferred)

**`users` table:**
*   `id` (Clerk User ID, PK, VARCHAR)
*   `name` (VARCHAR)
*   `email` (VARCHAR, UNIQUE)
*   `image_url` (VARCHAR)
*   `subscription_status` (VARCHAR, e.g., 'free', 'pro')
*   `created_at` (TIMESTAMP)
*   `updated_at` (TIMESTAMP)

**`projects` table:**
*   `id` (UUID, PK)
*   `user_id` (FK to `users.id`, VARCHAR)
*   `original_video_url` (VARCHAR, S3 URL)
*   `status` (VARCHAR, e.g., 'uploaded', 'transcribing', 'analyzing', 'completed', 'failed')
*   `transcription` (TEXT, raw Deepgram output)
*   `caption_data` (JSONB, Deepgram generated captions, SRT format implied)
*   `created_at` (TIMESTAMP)
*   `updated_at` (TIMESTAMP)

**`short_videos` table:**
*   `id` (UUID, PK)
*   `project_id` (FK to `projects.id`, UUID)
*   `title` (VARCHAR)
*   `description` (TEXT, AI-generated)
*   `start_time_sec` (INT)
*   `end_time_sec` (INT)
*   `reason_for_engagement` (TEXT, AI-generated)
*   `seo_score` (INT, 0-100)
*   `caption_for_clip` (TEXT, specific to short clip, potentially derived from `caption_data`)
*   `caption_style_id` (FK to `caption_styles.id`, UUID, NULLABLE)
*   `rendered_video_url` (VARCHAR, S3 URL, NULLABLE)
*   `status` (VARCHAR, e.g., 'pending', 'rendering', 'rendered', 'failed')
*   `created_at` (TIMESTAMP)
*   `updated_at` (TIMESTAMP)

**`caption_styles` table:**
*   `id` (UUID, PK)
*   `user_id` (FK to `users.id`, VARCHAR)
*   `name` (VARCHAR, e.g., 'Bold Yellow', 'Modern')
*   `font_family` (VARCHAR)
*   `text_color` (VARCHAR, e.g., '#FFFF00')
*   `highlight_color` (VARCHAR, e.g., '#000000')
*   `max_words_per_line` (INT)
*   `font_size_scale` (FLOAT)
*   `position` (VARCHAR, e.g., 'bottom', 'center')
*   `is_default` (BOOLEAN)
*   `created_at` (TIMESTAMP)
*   `updated_at` (TIMESTAMP)

**`social_accounts` table:**
*   `id` (UUID, PK)
*   `user_id` (FK to `users.id`, VARCHAR)
*   `platform` (VARCHAR, e.g., 'youtube', 'tiktok', 'instagram')
*   `platform_user_id` (VARCHAR)
*   `access_token` (VARCHAR, encrypted)
*   `refresh_token` (VARCHAR, encrypted)
*   `connected_at` (TIMESTAMP)

**`scheduled_posts` table:**
*   `id` (UUID, PK)
*   `short_video_id` (FK to `short_videos.id`, UUID)
*   `social_account_id` (FK to `social_accounts.id`, UUID)
*   `post_title` (VARCHAR)
*   `post_description` (TEXT)
*   `scheduled_time` (TIMESTAMP)
*   `status` (VARCHAR, e.g., 'scheduled', 'publishing', 'published', 'failed')
*   `published_url` (VARCHAR, NULLABLE)
*   `created_at` (TIMESTAMP)
*   `updated_at` (TIMESTAMP)
